## Ownership and bounds

`Retained<R,D,G>` owns typed route metadata and the **existing** entry `ScopeOwner` plus `PresentationLease`. It does not own another document/history/model/UI tree. Source and structured authorities remain separate. Routes should be small typed application identities; flow neither interprets URIs nor bounds arbitrary caller payload sizes.

Each tab is a direct child of its exact registered World. An entry is a direct child of its exact tab. `add_tab` checks coordinator membership and World ancestry; new entries must have the tab's actual parent liveness. Push captures `after`, replace captures `old`, and select/back/forward capture exact retained entry IDs before submission. Replace preserves its old history position. Back/forward/select never dispose retained entries. Push protects every truncated forward entry; replace protects its old entry; close protects its entire explicit entry set. Shared documents are never implicitly closed by presentation disposal.

Defaults are 64 tabs, 512 installed entries, 64 total charged queued/pending operations and 64 retained terminal outcomes. New entry ownership in queued commands adds at most one entry per charged operation; close vectors cannot exceed the configured entry limit. No LRU eviction, implicit suspension or tombstone log. Application route payload size, native document bytes/history and destructor duration remain application/native costs. `HistoryCounts`, F3 `Counts` and F4 `WorkCounts` are separate observations, not latency budgets.

The callback-safe sender resolves no contextual targets. Identical outstanding close sets coalesce to the same operation. Conflicting tab operations queue; independent tabs proceed. Submission, authority/serial/decision exhaustion and capacity refusals do not replace valid work. A refused submission returns its owned command. Later validation failure is an asynchronous Failed outcome, not installation of the proposed entry. Dropping the retained owner closes sender admission and releases queued ownership outside the inbox borrow. Route/resource destructors may submit another bounded command; no callbacks run while that queue is borrowed.

## Decisions, saves and atomic commit

Operations own Queued / AwaitingDecision / Saving / Failed / Ready / Committed / Cancelled state. A displayed `DecisionId` is bound to operation authority, incarnation and round. Duplicate, foreign and stale decisions/saves cannot operate a current guard. Observer ticket drop or elapsed time has no decision authority. Explicit operation cancel is available while saving; a stale displayed decision cannot cancel a newer save round.

`TransitionHost` is the small synchronous admission/validation seam, not a service framework. Its concrete `ProtectionPass` freezes **real native writers**, captures native revisions, and holds every presentation lease (including hidden and other Worlds). It preflights the complete affected set. `TransitionHost::validate_entry` is a required observational, callback-free check of an incoming document's native identity and exact presentation lease. The concrete adapter checks live document/manager, exact registered native target and exact held lease-to-scope/document association (not merely the existence of another lease). It runs for push/replace/select at admission and again at commit. Immediately before a retained commit, exact command resolution (including incoming owner/parent, tab and truncation set), every document and participant snapshot are validated again, with no await/reentrant callback between final validation and metadata removal. All removed owners leave metadata before resource destruction. The protection guard survives their destruction. A participant loss rejects the whole commit; it does not retire a second valid entry.

Saved revision metadata is not a second document store. Initial saved revisions come from the host's actual persistence state; `None` is conservatively dirty. A save result changes that metadata only after exact ticket/revision/lease validation and success. Informed discard marks only this protection safe; it does **not** mark the document saved. Completed external persistence is not rolled back by later cancel/failure. Cancel without completed persistence preserves bytes, revision, native history, selection and installed resource ownership.

Synchronous `save` catches a host persistence callback at the actual immutable native authority. `save_source` writes the exact frozen source bytes with `write_all` and `sync_all` to a host-authorized path. It is not an atomic file-replacement/directory durability or destination-security policy. Structured persistence uses the native structured authority and host's existing encoder, not a flattened source substitute.

For existing asynchronous/external producers, mint exactly one `SaveWork` via `own_save` / `own_native_save`. Keep it with that actual job on the existing executor/thread; `run` normalizes failure/panic and returns an owned result. Dropping the actual job or undelivered result records loss, leading to Failed with freeze retained. Copying/dropping an observer `SaveTicket` does nothing. `complete_owned_save` / `complete_native_owned_save` perform the authoritative exact-revision acknowledgment. A separate synchronous callback cannot acknowledge an already-claimed job. These types do not spawn work, claim backend termination, replace F4 exit accounting, or wait for quit/navigation before permitting saves.

## Native composition sequence

1. At **window creation**, register its exact `WorldOwner`, bind it to the World local slot and install the existing native `CloseGuard`. Register every authoritative native source/structured document in `ProtectionHost` with its exact manager World and flow document identity. Every presentation owns a normal F3 lease. Include hidden and shared presentations; never infer affected entries from selection/focus.
2. Let the existing renderer `CloseDrain` request/coordinate native guards. Before returning to the destructive runner boundary, and after host callback batches, construct exact `HostWorld`s and call `sync_native` with **every live registered World**. Do not ignore an adapter error and proceed to destruction. There is no automatic plugin installation or mandatory behavior change for ordinary apps.
3. Present the exact owned native decision. Save lanes run independently of retained navigation/quit scheduling. Failure remains Failed and frozen until explicit retry, informed discard or cancel. Native retry allocates a fresh native request while retaining freeze; old decisions/save tickets cannot satisfy it. Save/Discard/Cancel preflight the exact native request and World before consuming any attempt. Omitted/foreign/stale admission retains the prior operation, decision round and freeze; only successful Save admission can retry the native request. Technical save failure remains owned/frozen, never implicit cancellation.
4. A World's native Ready retains protection and **does not dispose any entry**. If that World owns the actual native document manager, every lease outside it must belong to an actually consumable dependency-closed teardown cohort before manager Ready is published. Starting with all validated phase-Ready attempts, the adapter repeatedly removes managers with any held lease outside the remaining cohort, to a greatest fixed point. Removing a blocked B therefore also removes a manager A that B presents, transitively; jointly Ready cycles survive when they have no outside blocker. Phase-Ready alone is insufficient. This assumes native requests represent actual active runner closes, not fabricated guard requests for non-closing Worlds; the missing Session hook must establish that scheduling/consumption fact. An application lease outside Worlds blocks manager teardown until explicitly released/restarted. This is ownership protection, not automatic model transfer: hosts wanting independent window closure must place shared native managers under their existing application-owned lifetime. A non-manager presentation can close without closing its shared manager. Participant withdrawal revokes a prior manager Ready before runner consumption. The unchanged `CloseDrain` retains primary/secondary/process-exit/cancel policy and waits for all participating guards. New flow World registration and new leases of protected documents refuse at their authoritative coordinator boundaries through Ready. `close_document` preserves its old idempotence/InUse policy and additionally refuses unleased frozen documents. Frozen structured authorities cannot be removed from their manager.
5. Native managers expose read-only exact identity enumeration. Unregistered manager documents, missing Worlds and lost leases cannot bless Ready. An unavoidable added native document invalidates Ready; register it and explicitly cancel/restart the attempt so the whole affected set is snapshotted again. Existing freezes survive Failed. The adapter does not invent a fallback target or silently omit an unleased native manager document.
6. Core content/history admission rejects source and structured programmatic writes, undo/redo, source reload, editor mutation and composition start under freeze, independently of UI readonly setters. Live composition and pending Input IME prevent snapshot admission without clearing preedit. Existing selection/read APIs remain available. The adapter requires every shared lease World and conservatively blocks its pending IME (and manager-World IME) rather than guessing a selected target. A missing shared participant stays queued; it is never treated as quiescent. Normal apps with no F5 freeze retain their previous behavior.
7. Only actual terminal WorldOwner loss after native consumption permits `reconcile_world_loss` to release native protection. Call `Retained::reconcile_world_loss` to abandon affected owned operations and release dead tabs/entries; queued commands keep exact stale targets and refuse, never target a reopened window. Then perform normal F3/F4 cleanup/drain/accounting. Do not fabricate backend exit acknowledgment. The host must retain the protection owner for the entire attempt; forced owner/process loss has the same explicit limits as F3/F4.
