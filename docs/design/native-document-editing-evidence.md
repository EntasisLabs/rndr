## Capability / gap matrix

Each row separates need from evidence and proposed ownership.

## Findings that change the earlier conversational audit

1. The source audit confirms CodeMirror **and** Tiptap consumers; Code Markdown already combines Tiptap with source-preserving block custody (M6/M7). Calling every rich surface “serialize the whole note” would be wrong.
2. Latest rndr has per-axis nested wheel remainder chaining and corrected clipped indicators (R9); interactive scrollbar behavior is still distinct backlog. Current DataTable/header corrections are not this epic's implementation scope.
3. Existing `edit_buffer` and native IME/clipboard plumbing are real reuse, not missing from zero. Their current entity/history/revision limitations are the gap, not a reason to replace all controls.
4. `VaultBufferCore::MarkSaved` replaces live content, not merely a baseline token (M8). Safe concurrent save acknowledgement needs an adapter/protocol decision, not an assumed expected-revision field.
5. Accessibility SetValue is deliberately **unsupported**, despite the decoder enum/match arm. The source-backed guard and action-advertising checks matter more than symbol presence (R8); a new editor must add validated semantic operations rather than restore raw full-value writes.
6. Full-document line-index rebuilding, gap relocation, snapshot history and reshaping on changes are observed code paths. Large-document slowness and cross-platform input defects are **not reproduced findings** in this docs-only exploration.
