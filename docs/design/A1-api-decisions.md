# A1 API / cardinality review decision record

Status: implementation candidate for independent owner review, **not A2 clearance**.

## Additive spellings and ownership

- `rndr_core::GenericInteraction` installs/reuses idempotent `Chrome` and uses its one Input → Update pipeline. No Shell, quit/file selection policy, second focus manager, dispatcher or runtime. Existing Focus/Input/World are authoritative. Plugin uninstall is unsupported; install once per App lifetime. Reinstall is a no-op and does not reset state or queues.
- A button opts in individually via `ReleaseActivation`. Unmarked Button retains press/legacy Enter and `Fired`. Modern buttons never also emit Fired. Existing public struct literals and AccessRole variants remain unchanged.
- `request_focus`, `cancel_activation`, `try_activate` are reusable core APIs. Host capture loss must call cancel; logical core capture does not assert native pointer capture. Pointer press arms, same-pointer in-bounds release commits; outside, Escape, blur, focus loss, disable/readonly/hidden, destruction or explicit capture cancellation rejects. Enter commits on nonrepeat nonsynthetic down; Space on corresponding up. Editor CapturesKeys retains keyboard ownership. Rich events own the legacy shim; no dual delivery. Matching registered hotkey chords and active physical-key guards take priority; mere registration of a nonmatching chord never owns the ordinary base-key gesture. Space/Enter release ownership is classified before clearing a guard, so a real owned release remains cancellation-only even after modifiers change. Synthetic/repeated/unmatched releases still cannot activate; a subsequent fresh ordinary gesture can. Space/Enter edges are retained in receive order whenever GenericInteraction is installed, regardless of pre-frame focus, until pointer focus and ordered Tab traversal determine their owner. Hotkey-owned control edges become synthetic cancellation-only markers (never an activation); all private release/synthetic edges are stripped before legacy widgets/editors run. A Space up always takes and resolves its arm, even after modifier/ownership changes; a modified, synthetic, repeated or unmatched release cannot commit it. Modifier/synthetic input conservatively cancels armed interaction.

## Canonical intent / supported cardinality

**Owner revision after REVISE of `f7aa9703b7258e5ed546fc8436b3676f2705d9b0`:** `ActionIntents` is a **bounded pending FIFO of 64 requests**, not 64 distinct targets. Each valid `try_activate` call is an independent intentional request, including repeated Enter presses, multiple AT requests and mixed keyboard/pointer/AT requests for the same entity before drain. Receive order and multiplicity are preserved up to capacity. Input does not clear pending requests. No coalescing or deduplication is performed: entity, source or frame alone do not prove the same gesture. There is no reliable cross-source correlation token in A1, so none is invented. Hosts/adapters must use one canonical producer per physical activation rather than emit both a direct activation and synthetic keys for it. The core pointer path commits only on matching release, keyboard commits Enter down or matching Space up (not both edges, repeats or synthetic events), and opted-in Buttons are excluded from the legacy Fired path.

`try_activate` returns `Accepted`, `Overflow`, or `Rejected`. At capacity every further valid request, even for an already-pending target, returns Overflow and increments the observable `overflow` counter; there is no eviction, overwrite or partial enqueue. Rejected targets do not consume capacity or increment overflow. This is bounded explicit backpressure, not an unbounded lossless-stream promise. No opt-in coalescing API is needed or added. **Revision to the new, not-yet-accepted A1 API:** removed `ActivationResult::AlreadyPending` and `ActionIntents::coalesced`; callers must handle Accepted/Overflow/Rejected. Existing pre-A1 public struct literals (Button, Input, Focus, Fired, AccessNode, etc.) are unchanged.

Scheduling: platform/hotkey filtering precedes Chrome Input. GenericInteraction applies pointer focus/arming first, then traverses rich keyboard events in receive order; raw pointer and keyboard timestamps are not merged into a new cross-device event stream. Modern requests enqueue through `try_activate`; AT can enqueue before Input and remains pending. The remaining rich queue stays in order, and its first unconsumed press rebuilds the legacy `Input.key` shim instead of a consumed Tab erasing a later Enter/navigation key. The rich queue owns its text/shim representations; downstream widgets must not process both. Existing CapturesKeys/editor ownership and legacy press/Fired single-slot semantics are retained, not upgraded into an arbitrary multi-target legacy event stream. Chrome's existing Update runs legacy actions/buttons; hosts drain the modern queue during Update with `take_action_intents`, after any producers they need included in that drain. Later producers remain for the next drain; delayed hosts retain pending requests and can overflow. Core input callers must clear per-frame Input edges at the normal runner boundary; repeatedly submitting the same down event as a fresh request is not a deduplication service.

Drain revalidates generation, visibility, enabled/readonly and unchanged action name, rejecting obsolete intents. An opaque intent is not authorization to execute commands; hosts retain command permission/argument validation. Library never executes networking/actions. Legacy Fired remains its historic single-slot path for unmarked controls only. No automatic bridge fans the modern queue back into Fired. Owner retains independent exact-candidate re-review/acceptance before A2; this implementation does not grant it.

## Accessibility and tabs

- `Semantics` adds explicit persistent name, description and interaction-readonly; placeholder and current text value are not persistent names. Composed visible labels are folded into Button names. Non-label interactive descendants are not folded.
- `access_details` supplies allowed focus/activate/SetValue flags and relations without extending AccessNode literals. `try_apply_access` returns observable `AccessCommandResult`; compatibility `apply_access` delegates. Hidden/stale/disabled/readonly/unsupported requests are denied. Core and AccessKit use the same matrix.
- All AT SetValue requests explicitly return `UnsupportedSetValue`; none mutate Label, Buffer, Caret, IME or history. Native bridge no longer advertises SetValue. This is a deliberate safety fix to reproduced bypasses, not a claim that AT text editing is complete. Ordinary legacy keyboard/IME editing is unchanged. Semantics.readonly also constrains opted-in user text/IME/clipboard mutation while preserving navigation/selection/Copy. It is not programmatic document-write authorization: validated host/source-edit APIs retain their existing authority. No new text-entry widget is shipped in A0/A1.
- `TabRelation` / validated `link_tab_panel`, `move_tab_focus(TabFocusMove)` and existing Tabs/Tab/TabPanel provide real tablist–tab–panel relationships without a new A2 selector widget. Manual focus movement does not change selection. Canonical activation selects and synchronizes actual panels. Inactive panels are hidden from layout/paint/hit/accessibility; platform panels use TabPanel with controls/labelled_by. A2 still owns orientation/key mapping, roving entry policy, visible focus treatment, selector composition and overflow presentation.
