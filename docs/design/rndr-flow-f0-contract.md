Use no default features (`default = []`), and initially no optional features. Its sole direct runtime dependency is workspace `rndr_core`; standard-library collections/IDs suffice. ## 2. One disposal owner; several worlds; shared documents

**D** One host application coordinator has a process-local authority ID and a tree of scope metadata. Each window is explicitly registered with a distinct World registration ID. `crates/rndr_render/src/lib.rs::{Session::window, Handler}` owns a separate `App` per window; raw `Entity` values are meaningful only within that World. Cross-world operations pass owned messages/IDs through host wiring, never pointers/borrowed Worlds. A plugin in each World drains its own effects; it cannot reach other Worlds by looking up the same resource type. Cross-World scope tokens may share only coordinator-owned atomic liveness/generation metadata (never World/document mutable state). Global disposal marks those flags before sending drain messages, and every mutation consumer checks them: a lagging World must not accept a result merely because its local retirement message has not drained yet. A headless host can own just one World.

Ownership tree: application -> window -> tab -> retained entry -> surface -> semantic block. A document is instead application/document-manager owned; entries hold presentation leases to it, not a second disposal-parent edge. The document manager's stable domain ID/revision remains authoritative. One shared document may have leases in several Worlds. Closing an entry releases exactly that lease. Closing the last presentation **does not automatically destroy/save/cancel the document**: the manager retains the open document until an explicit guarded document-close operation closes admission, validates all leases and releases it. Application/window close determines the complete affected lease set; another lease/window admitted during preparation invalidates the transition snapshot. No ownership transfer, detach or reparent API in v1. Independently owned backend jobs are outside the UI tree from creation.

**I** Register/unregister World participants explicitly, guard registration during quit, and reconcile a dropped World as terminal loss of its UI scopes. No destructor can promise save durability. Cross-world shared-document mutation goes through the host document manager, not copies of `SourceSession`. `World`/entity IDs are projection handles, never shared document authority.

## 3. Incarnations, lanes and admission

**D** Opaque typed IDs use checked nonwrapping `u64` counters: coordinator authority, scope serial, cleanup serial, transition/decision serial. A scope serial is never reused during an authority's lifetime; if a slot arena is used internally, the public token still carries a new serial. Coordinator authority IDs are allocated process-wide without wrap; fail construction on exhaustion. Scope recreation, including the same chat key, gets a fresh serial. These are process-local IDs, not persisted/wire identities or permission tokens. A host reconnect uses its native authority/session/document IDs in addition, not a flow token serialized as authorization.

Request token = `(authority, scope serial, lane key, lane generation)`. Lane keys are typed by the application, bounded and interned without retaining user prose. Each lane has a monotonically checked generation; replacement increments it before cancel/drop of the old handle. Completion validates live owner, exact lane generation, exact domain target, and native revision/admission at the synchronous mutation boundary; no await or arbitrary callback between validation and commit. A published event is not recalled by handle cancellation (`runtime.rs` inbox and event queues).

- History load, mode read, feed instance refresh and save protection are separate replacement lanes. Replacing one must not stale every other activity as the preview's single scalar generation currently can.
- A stream is an ordered multi-result lane, not one generation per chunk: host checks authority/session/turn and increasing sequence. Duplicates/retired turns cause zero writes/revision/history changes. Catalog results may be application-owned; exceptions must not bless session-scoped responses.
- Admission of a task/cleanup either installs under a live owner, or returns the untouched value plus a typed refusal to the caller. Caller must cancel/drop/clean the rejected value; provide `must_use` wrappers. No callback runs inside admission and no rejected registration is silently leaked.
- Counter exhaustion refuses the new operation **before** partial mutation or cancellation of currently valid work. The old lane remains usable for its outstanding result; the host may explicitly dispose it. No wrapping, saturation aliases or token reuse. Test with injected near-max counters. Core entities currently wrap `u32` generations (`world.rs::despawn_entity`); flow must not inherit that as its identity contract. Existing close tokens are an independent native contract, not flow's counter source.

## 4. Hidden, suspended and closing

| State (D) | Activity/result policy | Exit |
| --- | --- | --- |
| Visible | Normal owned work/admission | Hide, suspend or guard close |
| Hidden | Retain document/entry/state and active observation lanes; same owner/revision checks | Show with no remount-derived reset |
| Suspended | Explicit per-activity suspension, never inferred from Hidden/offscreen. Cancel UI polling/observation lanes and advance their generations; retain model and last-good data. No new per-scope stream buffering in flow. | Resume starts fresh lanes and reconciles from host durable state/sequence; lost deltas must be recoverable or suspension is refused for that activity. |
| Closing, precommit | Retain resources/model while guards/choices run; freeze guard-relevant mutations (§6), permit required save/guard completion lanes | Cancel keeps intact live state; failure stays protected/frozen for retry/cancel; commit disposes |
| Disposed | Reject all work/results, even already published ones; cleanup may still drain | Never resurrect |

**E** `crates/rndr_core/src/tabs.rs` Hidden and Markdown host recycling affect presentation, not these semantic states. Feed interval polling is currently mounted-only (`rndr_liquid_ui/src/feed.rs`); timers use absolute `Time` deadlines and survive slot recycling (`timer.rs`). **D** Preserve those behaviors: hidden is not a new promise that offscreen interval polling runs. Suspended is opt-in and disallowed for an unrecoverable stream rather than silently losing events. Backend execution continues unless a separate host-authorized cancel command succeeds.

## 5. Logical disposal, drain and boundedness

**D** Disposal's linearization point marks the full owned subtree dead and invalidates all lanes/decision tokens before external effects. Release document leases through their one owner. Remove owned registrations from authoritative tables before invoking them. Snapshot children in creation order, then consume cleanup **postorder (children first, siblings in creation order), reverse registration order within one scope**. Signal/drop owned tasks/feeds before that scope's custom cleanups, outside registry borrows. Parent cleanup sees children logically dead and their cleanup attempted, not necessarily worker IO quiescent. Repeat dispose is a no-op returning the existing outcome.

Reentrancy: callbacks may enqueue requests but cannot recursively mutate the coordinator. Queue them FIFO and revalidate after the current callback/cleanup batch. Registration against a dead scope refuses and returns ownership. A listener can remove itself/another listener; admission/dispatch rules are in §8. No locks/World resource borrows held while calling host code or awaiting work.

A **drop token only signals** cancellation/removal using an atomic flag/owned queue; it never mutates World from Drop and never runs arbitrary callback there. Logical rejection is immediate from that flag or owner liveness. Physical removal runs on the UI-thread drain. Future plugin contract: drain at the start of Update before timers/feeds/result consumers, plus after callback batches and at end of Liquid PostUpdate reconciliation. Commands arriving after a drain wait for the next pump, but admission must already reject dead owners. Core schedule ordering is inspected in `app.rs::App::update`; there is no universal terminal hook in current `hierarchy.rs::despawn`, and its cascade order is **not** child-first. Do not change core cascade semantics to pretend the flow ordering is already supplied.

Cleanup `Result::Err` is recorded and remaining independent cleanup attempted. For unwind-capable explicit callbacks, catch at the callback boundary, record `Panicked`, continue; never treat it as save success. An unfinished guard task/error/panic/lost completion remains Pending/Failed with cancel/retry UI, never Ready. Do not promise recovery from arbitrary destructor double-panic, `panic=abort`, process kill or crash. Distinguish logical disposal, cleanup attempted, cooperative task drain acknowledged, blocked/unknown external work, and external backend execution. Disposal outcome does not mean all IO stopped. Existing local/background runtime panic behavior differs; an adapter must normalize explicit terminal outcomes or conservatively expose unknown failure, not infer a result from silence.

**D capacity policy (initial defaults, design budgets not measurements):** 4,096 live scopes/application, 32 lanes/scope, 256 cleanups/scope, 64 retained entries/tab, 256 pending transitions/application, 1,024 queued reentrant commands/application, 256 cleanup invocations/pump, and 512 terminal/diagnostic events in a payload-free ring. Configurable at construction; validate positive finite bounds before admission. Exceeding live/pending/command/history budgets returns Capacity without partial mutation or silent eviction. Disposal/cancel and authoritative retirement must always progress: keep a pending-dead bit and ownership data in already admitted slots and scan it incrementally; correctness cannot depend on allocating a cleanup queue entry. Never drop cleanup because a queue is full. Drop signals use existing token storage, not an unbounded queue. Ring overflow evicts oldest diagnostic only and increments a dropped counter. Terminal observation can expire; stale rejection depends on nonreused IDs/current membership, not immortal tombstones. Dispose work over budget continues in later pumps with pending count exposed. No automatic dirty-history eviction/approval.

## 6. Guard policy: freeze, not distributed revision invalidation

**D** Freeze guard-relevant mutation at the **authoritative host writer**, from snapshot admission until explicit cancel/abandon or committed disposal; freeze remains through Failed while retry/discard is pending and through native Ready consumption. Cancel abandons the exact decision before releasing freeze; failure alone does not reopen writers under an outstanding discard choice. That includes text and IME commits, undo/redo, reload, programmatic/agent writes, attachment/model changes that a guard protects, lease/topology changes and queued external completions. Existing in-flight IME must be committed/cancelled through the editor owner before taking the snapshot; if that is not possible, block the transition, not silently lose preedit. Save/guard-result lanes remain live and must not need the transition lane being awaited. Reads/rendering/selection and unrelated documents continue. Explicit topology changes may instead invalidate and restart the whole attempt before it reaches Ready; they cannot silently join an approved snapshot.

Why: native `CloseGuard` allows freeze or invalidate-on-every-mutation (`crates/rndr_core/src/close.rs`). A distributed invalidation-only scheme is not evidenced across all future Medousa writers. Freeze makes the contract enforceable at one host admission boundary. The owner still revalidates document incarnation, dirty revision and participant/lease revision before commit. An unavoidable external change invalidates native protection and restarts; it is never allowed under an old Ready. Freeze is an **I**, not a claim that current `SourceSession::readonly` or preview `loading` already implements all these hooks. Source `admit` guards readonly/composition/revision/backpressure; `SourceSession::{commit,undo,redo,reload}` and source/structured projection admission retain authority. Structured editing uses `structured.rs::StructuredDocument`, not the source history. Host import/reload/save adapters and future SDK application mutations must all route through the same freeze owner. No broad production hook is added by F0.

**D native composition:** retain `CloseGuard` resource for the entire attempt. Per-World host adapter snapshots and freezes all affected entries/doc leases (including hidden ones), initiates saves and exposes choices. Map exact flow transition to native `CloseRequest`; coalescing does not reuse a decision across different requests. Only after all protections, cleanup preparation and final revision/participant validation call `complete(request, Ok(()))`. Keep protected data alive/frozen through Ready; native committed World destruction terminates UI lifetimes. Native Idle/cancel releases freeze and cancels the pending transition, not already committed persistence. Failure calls `complete(Err)` and retains state. Informed direct discard is a host decision recorded as protection, not a forged durable save; use native `discard(failed_request)` only for its documented Failed state. Never remove/replace guard to bypass it.

**E** `rndr_render/src/close.rs::CloseDrain::step` drains all windows for primary close/quit, secondary close targets its World, any cancel cancels process-exit attempt, and dynamic participants remain checked. **I** Each World supplies host protection plus a shared-document manager coordination channel. No new flow native gate, no single-World assumption. New windows/leases during exit are refused or explicitly invalidate/restart protection. Forced termination remains out of scope. Tab/document close commits directly after final validation; native window close waits for runner destruction rather than disposing drafts early merely because one World became Ready.

## 7. Liquid semantic identity: stable host keys with conservative fallback

**E** `view.rs::{set_liquid_source,match_states,LiquidHooks,reconcile}` mixes parsed-equality carry, mounted/saved state and source-byte resource lookup; records override carry on mount. `state.rs::ComponentStore` is keyed `(Entity, source)`, `TimerStore` by `(Entity, source, step)`. `FeedWatch` is a physical root component; `FeedRequest` lacks owner/request context. `MarkdownSlotId` already forbids reuse and source anchors follow edits; a host-slot ID is not a semantic Liquid ID. In `view.rs::reconcile`, `source` comes from `MarkdownView::block_start`: it addresses **projected Markdown**, not raw original fence bytes. `rndr_liquid/src/{stream.rs,document.rs}` builds `LiquidStream::{blocks,markdown}` and nested block-token references (`Segment::Block`); their indices are parse-local, not durable identities.

**D** Add a host-supplied **sidecar**, not an untrusted fence grammar extension or a parser-wide new crate. Proposed keyed-source API accepts normalized source plus a complete **reading-order vector** of optional opaque stable keys (1–256 control-free UTF-8 bytes) for top-level settled block occurrences, and expected surface source revision. Enumerate these occurrences by the `Segment::Block` references in `LiquidStream::markdown()` resolved against `blocks()`, not by original fence offsets, projected Markdown offsets or raw block-vector index (nested blocks also occupy that vector). A pure occurrence-inspection helper exposes this same ordered description to hosts. Incomplete/pending fences get no live block identity until settled. Validate the entire input before mutation: valid occurrences, unique occurrence entries, keys unique among live siblings, revision current and bounds. Invalid/duplicate keys refuse the whole update with no source/state/lane change. The host, not rendered text, decides semantic sameness. Keys are scoped to one surface; equal keys in different views/Worlds cannot share UI state. Persistence of reader state is a separate future host policy, not automatic key restoration.

Internal key = `(surface incarnation, block serial)` with a host-key/source-occurrence index; serial checked/nonreused. Live same-key + same-kind maps to the same block serial; changed kind, explicit reset, disappearance or source-authority reset retires it. Removing then reinserting the same stable key creates a **new** serial even if bytes and record revision were identical. IDs are labels for matching currently live occurrences, never permission to revive retired state. A keyed replacement updates source positions atomically with all record/saved/mounted/timer/feed indices. A Markdown slot/root can be remounted without changing semantic identity; state never chooses identity by lookup precedence.

Fallback for **unkeyed settled blocks**: no-op source and append preserve existing identities; otherwise match a parsed block by complete semantic value equality only if it occurs **exactly once in both old and new unkeyed occurrence sets**. For this comparison and child-schema checks, recursively resolve nested parser block-token references to their parsed child values; a different parse-local token index is not itself a semantic edit. Malformed/unresolvable references refuse keyed input rather than alias another child. This is renderer-side comparison over existing parser output, not a grammar change. Match across reorder/prefix insertion. No greedy duplicate pairing, source-byte preference, or equality-hash-only identity. Ambiguous equal duplicates get fresh serials on non-no-op replacement, even if one appears at the same byte. Unmatched old blocks retire. Keyed and unkeyed occurrences never match each other implicitly. Changing identity mode requires an explicit reset/rebind, not opportunistic transfer.

| Operation | Keyed result (D) | Unkeyed fallback result (D) |
| --- | --- | --- |
| Exact no-op / empty append | Preserve serial, state and record revision | Preserve, including duplicates |
| Same key, same kind, content edit | Preserve block serial; child/resource compatibility rules below | Changed parsed value: new serial, default state; old retires |
| Different key at same source byte | Retire/reset, never consult old source record | Changed parsed value resets even at same byte (**C**, fixes P2 transfer) |
| Duplicate equal content | Distinct unique keys stay independent; duplicate key refuses transaction | Nonappend non-no-op replacement resets ambiguous groups; append leaves completed duplicates intact (**C**, replaces greedy pairing) |
| Reorder / prefix insertion | State follows currently live key, source metadata remapped | Unique equal values follow content; ambiguous groups reset |
| Kind change under same key | Retire serial, timers/feed requests, default new kind | Retire/new serial |
| Offscreen edit / reorder | Same rules as mounted; no separate saved-state policy | Same uniqueness/equality rules; viewport is irrelevant |
| Remove, pump, reinsert same key/bytes | New serial/default; retired updates reject | New serial/default; no historical equality search |
| Atomic replace retaining same live key/bytes | Preserve (no intervening absence) | Unique equality preserves; duplicates follow rule above |
| Streaming append / complete pending fence | Preserve settled prefix; new settled blocks get new serials | Same; parser pending index must not alias a settled block |
| Explicit block reset | Fresh serial, default state/resources; old token stale | Same, even if source unchanged |
| Explicit surface reset / remove Liquid authority | Fresh surface incarnation, retire all descendants | Same; no rehydration from old entity/source records |
| Destroy view then recreate at recycled ECS index | New surface incarnation; no record transfer | Same |

**Child/state compatibility (D):** same stable block key is not a mandate to preserve incompatible indexed state. For accordion/tabs/checklist/selection/carousel/slides/recipe, compute an ordered child schema from complete parsed child values (not just count/label hash). If it changes—including child reorder, label/body change, add/remove—reset that block's child-index state, affected timers and nested child surfaces; keep the parent serial but increment its state revision and resource lane generations. Unchanged ordered children preserve their state when a parent title/style changes. This is an intentional conservative v1 policy, not a claim that props lack IDs: `rndr_liquid/src/props.rs::{RecipeStep,AccordionItem}` and several other child props already have IDs, while `state.rs::LiquidComponentState` still stores indices and not every child kind has a uniform durable-ID contract. Include existing IDs in schema equality/host payloads; do not reinterpret them as universal block/incarnation IDs. Per-child reader-state remapping is deferred rather than guessed from labels or generated ordinal IDs. Scalar/top-level state is preserved only when its variant and validity domain are unchanged; otherwise reset that variant and revision. Range changes invalidate selection rather than clamp to an unrelated item. A recipe step's duration/spec change resets its timer; unchanged recipe schema keeps absolute deadline across recycling. Feed/tile request identity includes instance, feed_id, datatype and field; any binding change retires that request lane, clears incompatible last-good state and issues fresh context. Cosmetic parent edits retain compatible feed data. New records after reset begin at revision zero/missing; preserved records bump on actual reset/change, not on source movement/no-op. All counters checked; exhaustion refuses before source publication.

Nested Liquid surfaces belong to their enclosing semantic block/child path, not transient nested Markdown entities. A physical rebuild/recycle keeps logical child resources when parent/child schema survives; semantic child removal/reset retires that subtree child-first. **I** separate a logical surface lease from physical `nested()` view destruction; parent retirement must not mistake a newly rendered nested Entity for the prior owner. F1/F2 tests must include nested controls, not assume top-level cleanup proves this.

## 8. Compatibility and removable listeners

**D** Keep existing `liquid_view`, `set_liquid_source`, `push_liquid_str`, source-key queries and legacy `subscribe_liquid_interactions(world, handler) -> ()` signatures. Legacy subscriptions remain explicitly **application/World-owned until World destruction**; ignoring a newly returned RAII handle must not immediately unsubscribe them. Add a separately named owned alternative returning a nonclone removal token, with explicit `unsubscribe(&mut World, token)` and Drop signalling. Owned view subscriptions also carry surface incarnation and retire with it. Global owned subscriptions are allowed but explicitly host-owned. Monotonic listener IDs and immediate cancelled flags reject stale handles; no `detach` escape hatch is needed—call the old app-global API intentionally.

Dispatch ordered by registration serial: take a snapshot of IDs, not move/overwrite the authoritative handler table. Insertions during dispatch start with the next envelope. Removal before a handler's turn skips it; self-removal permits its current invocation to finish and releases capture at the drain. Recursive emissions queue FIFO; no recursive handler borrow. After each callback apply queued removals before the next handler; bounded capacity refusal must not lose admitted registrations. A terminal surface rejects further delivery during the same batch. Catch explicit callback unwind as in §5 and retire the failing owned listener; legacy panic is reported and dispatch continues where unwind is supported. **E** current `state.rs::emit` takes the handler vector and later assigns it back; registration during callback can be overwritten. F1 must fix that behavior without requiring flow.

Source-key queries stay **current position lookups**, returning current record metadata, not durable identity handles. **C** after retirement they return None instead of leaked data; changed/ambiguous blocks no longer inherit positional state. Legacy `put_liquid_component_state(view, source, expected, state)` remains synchronous positional compatibility: require a live compatible occurrence, refuse stale/dead/missing owner, respect current revision and return existing `LiquidRevisionError` without mutation on rejection. It cannot prove a delayed writer intended the newly occupying occurrence if revision happens to match. Document it as unsafe for deferred/asynchronous target selection, not memory-unsafe Rust. Do not claim retroactive stale-safety for this insufficient signature; keep it only for immediate current-position callers. Preserve public structs/exhaustive matches in this phase; map legacy rejection to the existing error and expose richer reasons in the new API.

**I** Add separately named handle-based query/update/reset APIs with `(surface incarnation, block serial, expected state revision, expected resource lane generation where relevant)`. Retired handles reject even when new state revision is zero at the same byte. Return typed StaleOwner/StaleBlock/StaleRequest/Revision/Kind/Capacity/Exhausted before writes/rebuild/events. Do not add required fields to legacy public record/envelope/FeedRequest struct literals: use new handle-bearing records/envelopes/context types and additive methods. New code/SDK adapters must use these handles. Existing synchronous callers can migrate incrementally; no automatic import of orphaned old store entries.

Feed seam: additive `LiquidHost::load_feed_for(world, context, request)` with default delegation to existing `load_feed`; context identifies surface/block/request lane. Add explicit retirement notification with default no-op, invoked outside borrows. New host adapters return/store cancellable **observation** handles by context; retirement requests their local release. A legacy opaque `Pending` host can continue work: renderer invalidates and rejects its completion but cannot assert cancellation/quiescence. Context is not a backend cancel request or permission. Preserve old method and request layout; do not infer hooks from `FeedRequest.instance`. Flow may later own adapter handles but is not required for renderer cleanup.

## 10. Decisions versus remaining gates

All design alternatives above are settled for this phase; no new principal product decision is needed to write F1/F2. Required gates are evidence/authority, not another menu: sender review/native integration of these docs; separate implementation grants; F1/F2 tests and source compatibility review; actual application adapter/multi-tab/document/approval work under Medousa authority; exact locked offline build; four workflow proofs and native acceptance. Session-targeted backend cancellation cannot be upgraded to exact-turn CAS by flow: either retain its explicit current-session semantics or obtain a separately authorized backend API change before claiming a stricter oracle. No backend change is requested here.

The companion remains a decided design, **not** a newly created package. See the slice document for bounded F1/F2 interfaces, migration sequence, deterministic measurement and prerequisites. F3+ may be designed against this contract but implementation/release cannot claim F1/F2 or real workflow readiness from this record.
